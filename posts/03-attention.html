让一种信息读懂另一种信息

注意力、视觉 token 与跨模态融合

多模态训练 · 第 4 篇

对齐之后，为什么还需要融合

图文检索可以分别编码两种输入，再比较它们的向量。但问题“这张照片里左边的人拿着什么”需要根据问题选择相关视觉证据。一个固定的全局向量可能压缩掉必要的细节。

融合让信息在处理过程中发生交互。注意力是实现这种交互的一种机制。

把注意力看成一次可学习的读取

Attention(Q, K, V) = softmax(QKᵀ / √d) V

沿键的位置归一化匹配分数，再对值进行加权读取。

Q 是查询，K 是用于匹配的键，V 是被读取的值。先用 Q 与 K 计算匹配分数，再沿候选键的方向做 softmax，得到权重，最后对 V 加权求和。

这是一种计算解释，并不保证每个注意力权重都对应人类可理解的“关注原因”。不能只凭一张热力图就证明模型的决策机制。

用形状检查理解

省略批次与多头维度，设问题有 L 个 token，图片有 N 个视觉 token：

张量 形状 含义
Q [L, d] 每个文字位置发出的查询
K [N, d] 每个视觉位置的匹配特征
V [N, d_v] 每个视觉位置携带的内容
QK 转置 [L, N] 文字对视觉位置的匹配
输出 [L, d_v] 每个文字位置读取的视觉内容 
# q: [B, L, d], k: [B, N, d], v: [B, N, d_v]
scores = q @ k.transpose(-2, -1) / (q.shape[-1] ** 0.5)
weights = scores.softmax(dim=-1)
output = weights @ v

自注意力的 Q、K、V 来自同一序列；交叉注意力可以让它们来自不同来源。多头注意力则允许多个投影空间同时参与计算。

图像怎样成为 token

一种常见方式是把图像切成若干小块，再把每块映射为向量。对于高宽都能被块大小整除、没有额外裁剪和合并的情况，块数是 (H/P) × (W/P)。

位置编码帮助模型区分空间位置。提高分辨率通常能保留更多细节，也会增加 token 数量。标准稠密自注意力的两两交互计算随序列长度平方增长；实际显存还受注意力实现、检查点和精度影响。

三类结构的取舍

结构 信息怎样交互 适合思考的取舍
双编码器 编码后比较表示 便于提前建立检索索引
交叉注意力 一个序列读取另一个序列 可以反复进行条件化交互
视觉 token 接入语言模型 视觉与文字进入共同处理流程 复用语言模型，但增加序列负担

没有一种结构对所有任务都最优。选型要结合输出形式、输入长度、延迟和训练预算。

本篇练习

用两个文字查询、三个视觉位置，手算一个小型注意力矩阵。让其中一个键与某个查询更加相似，预测权重变化，再用程序验证。

验收：能正确选择 softmax 的维度；能解释为什么注意力输出的序列长度由 Q 决定；能区分对齐与融合。
