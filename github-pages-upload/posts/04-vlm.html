视觉语言模型到底训练了什么

多模态训练 · 第 5 篇

一张图怎样参与下一词预测

视觉语言模型的一种常见结构是：视觉编码器提取图像特征，连接模块把特征转换成语言模型可使用的表示，语言模型结合问题生成答案。

图像 → 视觉编码器 → 连接模块＋ 问题文本 → 语言模型 → 答案

连接模块可能是线性层、多层感知机或更复杂的查询结构。它不只是“把维度变成一样”：训练还需要让这些输入表示对后续任务有用。

训练目标仍然可以是预测答案

p(y | I, q) = ∏ₖ p(yₖ | y₍<ₖ₎, I, q)

给定图像、问题与已知答案前缀，逐个预测答案 token。

训练时，模型通常能看到正确答案的前缀，再预测下一个 token。这个过程称为 teacher forcing。推理时则使用自己已经生成的前缀，两者的输入分布并不完全相同。

模型的输出流畅，不足以证明内容符合图像。语言先验可以帮助生成，也可能让它在视觉证据不足时给出看似合理的回答。

分阶段训练在解决什么

一种教学上便于理解的策略，是先利用已有视觉编码器和语言模型，训练连接部分，再通过问答和指令数据训练任务行为。具体冻结哪些模块、每阶段用什么数据，各种方法会不同，不能把这一策略当作统一规定。

BLIP-2 使用冻结的图像编码器和语言模型，通过 Querying Transformer 连接两者。LLaVA 展示了视觉指令数据与视觉编码器、语言模型组合的训练方式。阅读时要核对每阶段的参数更新范围，而不仅记住架构图。

标签掩码为何如此重要

对于只监督助手答案的微调，一个样本可以包含提示、图像位置、用户问题和答案。输入需要保留这些上下文，但损失只在指定答案位置计算。上下文位置的标签通常设置为忽略值。

# 概念示例：labels 与 input_ids 已按模板对齐
labels = input_ids.clone()
labels[~answer_mask] = -100
outputs = model(input_ids=input_ids, labels=labels, **image_inputs)
loss = outputs.loss

这里的图像输入和模型调用依赖具体模型，并不是通用可运行脚本。许多因果语言模型会在内部移动预测与标签的位置；必须检查实现，避免重复移位。注意力掩码和标签掩码也不是一回事：前者控制可读取的信息，后者决定哪些位置计入损失。

冻结参数，不等于停止梯度传播

假设只训练连接模块，语言模型参数被冻结。为了更新连接模块，仍然需要知道语言模型输出对输入的导数。

for parameter in language_model.parameters():
    parameter.requires_grad = False

visual_tokens = projector(vision_features)
# 此处仍需保留计算图，让梯度到达 projector
outputs = language_model(inputs_embeds=visual_tokens)

不要把这段语言模型前向整体放进 no_grad()，否则上游可训练连接模块的梯度路径可能被切断。相对地，如果视觉编码器完全冻结、其前面也没有待训练模块，那么通常可以不记录它的前向计算图。

本篇练习

画出视觉编码器、连接模块、语言模型和损失之间的路径。分别标出“参数更新”和“梯度必须经过”的模块。再挑一个实际模型，检查处理器如何插入图像 token、如何创建答案标签。

验收：能解释答案损失为什么能训练视觉连接模块；能检查模板、标签与图像输入是否一致。
